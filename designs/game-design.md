# SisterGame（仮題）ゲームデザイン

## コンセプト

骸骨騎士とシスターが、魔物の暮らす3Dダンジョンの奥を目指すアクションRPG。プレイヤーは騎士自身を操作する。道中で出会ったNPC魔物の頼みを引き受けると、シスターの召喚に応じる仲間が増える。普段はお気に入りの少人数と歩き、魔物がひしめく大広間では、これまで結んだ縁が援軍となって現れる。

対象は探索とアクションが好きなプレイヤー。召喚魔物は種ごとの役割に沿って動き、騎士の簡易指揮に応じる。シスターだけは、プレイヤーが支援や行動の条件を細かく設定できる。PC向けの一人用を基本とし、コンソールは将来候補。本編の長さは従来案の約20時間を目安に、探索と総力戦の密度を試して見直す。

## コアループ

1. **少人数で探索する。** 骸骨騎士が道を切り開き、シスターと少数の召喚仲間が同行する。分岐や近道を見つけ、マップの敵と戦い、NPC魔物に出会う。
2. **NPC魔物と関係を結ぶ。** 依頼や物語イベントを終えると、誰が何のために力を貸すのかが分かる。そのNPC本人や、その仲間の魔物を呼べるようになる。どのイベントがどの召喚対象を解放するかは作者が指定する。
3. **次の場所に合わせて編成する。** 呼べる種類と一体あたりの召喚コストを見て、種類と体数を選ぶ。同種を複数体並べる編成も成立する。探索では同行する個体が見える程度に人数を絞る。
4. **ここぞという場所で援軍を呼ぶ。** 増援枠を設定した集団戦では、その遭遇に限って増援を呼べる。味方に入口を任せ、騎士が奥の敵に届くなど、増援が騎士の攻め方を変える。
5. **遠征を続ける。** 戦いで道が開いたら通常の探索編成へ戻る。新しい魔物の得意技、騎士の装備や移動能力を手に、次の区画や以前見つけた分岐に向かう。

### 最初に遊べるようにする一場面

坑道の工兵長を助けると、シスターがゴブリン工兵を呼べるようになる。帰り道で一体を連れて歩き、次の魔物溜まりでは同じ工兵を増援に組み込める。工兵が側道を支える間に、騎士は橋を渡って奥の術師に迫る。出口では普段の一体が再び隣を歩く。工兵と橋は、この流れを一部屋で確かめるための例である。

## キャラクターと加入

| 登場者 | 遊びの中での役割 |
|---|---|
| 骸骨騎士 | プレイヤーが直接操作する。武器、盾、回避、位置取りで戦況に参加し、群れの中でも自分が次に攻める相手や場所を選ぶ。 |
| シスター | 騎士の常駐の相棒。既存の支援・連携に加え、解放済みの魔物を呼び寄せる。誰が応じたかを登場位置や演出で伝える。 |
| NPC魔物 | 独自の事情とイベントを持つ登場人物。イベントの結末が召喚解放につながり、探索を先へ進める物語にもなる。 |
| 召喚された味方 | 解放した種類から、コストの許す数だけ編成する。同種でも戦場では別々の個体として移動し、標的を持ち、攻撃や巻き込みを判定する。 |
| マップの魔物 | 通常の戦闘相手。戦闘中の勧誘や撃破による自動加入は設けない。既存の混乱が一時的に陣営を変えても召喚一覧は変化しない。 |

物語上の戦闘イベントでは、救援に駆けつけた魔物とその場で共闘し、指定した展開を経て加入できる。その場限りの加勢と、次の探索でも呼べるようになる時点をイベント側で指定する。通常戦でも**解放済みの魔物を呼ぶこと**と**新しい種類が加入すること**は別の操作として扱う。

## 編成と召喚コスト

- 編成画面には解放済みの種類、一体あたりのコスト、選んだ体数、合計とその場の上限を示す。同じ種類をもう一体足すと、その一体分のコストを加算する。
- 召喚を受け付けるとき、人数枠とコスト枠の両方に収まることを確認する。たとえば残りコストが3なら、コスト1の援軍は3体、コスト3の援軍は1体を選べる（人数枠に空きがある場合の説明用の値）。
- 探索編成は騎士とシスターに同行する少人数を選ぶ。総力戦ではその編成を土台に、追加で誰を何体呼ぶかを選べる。追加枠の終了でNPCとの縁や保存した探索編成が失われることはない。
- 出撃で使う種と体数の組み合わせを、複数の召喚デッキとして保存できる。指定遭遇の増援デッキは枠が開く前から準備できる。出撃時にプリセットを読み込み、その出撃先の人数枠・コスト枠を照合して確定する。増援用に選んだデッキは通常探索の確定編成と別に扱う。
- 召喚コストは、まず同時にどれだけの戦力を編成できるかを表す予算として設計する。既存の支援魔法のMP、ショップの通貨、騎士の装備重量とは別に扱う。呼び直せるタイミングや戦闘中の補充方法は試作で決める。

## 探索、魔物溜まり、ボス

3D遭遇では `Boss` と `GroupBattle` を独立して設定する。魔物溜まりは集団戦の一例で、集団戦として作るボス戦は両方を有効にする。集団戦中の陣形と号令は `GroupBattle` で有効になり、増援は追加の人数・コスト枠を設定した集団戦で呼べる。突破、撃破などの達成条件は遭遇ごとに指定する。

ボス撃破の試作では、配置したボス個体の死亡でクリアし、周回・ボスID・前提フラグの条件を満たす場合に召喚候補を解放する。[3Dボス戦の設定](systems/BossSystem.md#3d遭遇での設定)

| 場面 | 編成 | 騎士が担うこと |
|---|---|---|
| 通常探索・通常戦 | 通常の少人数枠。強敵が偶然集まっても探索枠を保つ。 | 敵の予備動作を読み、相棒と連携する。NPCとの会話、装備の発見、近道の開通にも時間を使える。 |
| 魔物溜まり | 設定した人数・コスト枠を遭遇中に開く。終了・撤退・区画退出時に探索枠へ戻す。 | 援軍に横の入口を任せて騎士が正面を突破するなど、地形と部隊を活かす。 |
| ボス戦 | 通常は探索規模。戦闘全体または一局面を集団戦として設定できる。 | 集団戦では大勢が足止めして生まれた隙に接近するなど、ボスの予告を読む騎士の見せ場を残す。 |
| 二周目以降 | 対象に指定したボスを、解放条件を満たすとシスターの召喚候補に加える。 | 初周に見切った大技を味方側から読んで共闘する。通常の上限に収まるかは各ボスのコストと場面設定で決まる。 |

### 3Dの集団戦で読み取れること

奥行きと高低差を使い、前衛、後衛、側道、危険範囲が画面の中で見分けられるようにする。全員が同じ敵の足元に集まると、騎士の剣が届く相手も敵の予告も見えなくなる。狭い入口では先行者に道を譲る、別の入口があれば回る、射線上に味方が入れば範囲行動を見直す、といった振る舞いを試す。召喚魔物の動き方はその種に設定する。プレイヤーは戦場で「何を達成したいか」を指示できる。

一部屋の受入試験では、騎士の輪郭・危険な予告・増援の到着地点を見分けられるか、味方が入口を塞いで騎士の操作を奪わないか、戦闘後に増援が探索へ漏れないかを確認する。既存の同期・Burst比較は判断処理の参考値で、3Dの移動・衝突・描画を含む収容人数は実際の部屋で測って決める。[AIの検証記録](../docs/reports/experiments/2026-11-24_ai-terrain-gimmicks.md)

#### 騎士への攻撃予告（3D設計）

| 攻撃 | プレイヤーに伝えること |
|---|---|
| 範囲攻撃 | 個体へのロックの有無にかかわらず、発生前に実際に当たる床の範囲を赤い輪郭と薄い塗りで示す。橋の上に落ちる岩なら橋の上だけが赤くなる。攻撃が中断されたら予告も消える。 |
| 飛翔体 | その攻撃のロック対象に騎士が含まれる場合だけ、飛来側の画面端に短い赤い弧を出す。カメラの向きと弾道から表示方向を決める。ロック解除・弾の消滅・通過で弧が消える。味方を狙った弾や無照準弾が騎士のすぐそばを通っても弧は出さない。着弾時に爆発するなら範囲攻撃の床表示も適用する。 |
| 近接 | 通常の一撃は敵の構えと振りで読めるようにする。危険指定の技だけ、予備動作で既存の警告音を使う。近接用の画面端表示は追加しない。[ガードシステムの警告音設計](systems/ParryGuardSystem.md#ジャストガード不可攻撃の警告) |

橋で同じ方向から矢を放ち、騎士をロックしたときだけ右後方の弧が見えるかを試す。シスターを狙う爆発弾では着弾範囲だけが赤くなり、通常の流れ矢にはどちらの表示も出ない。近接の危険音が混戦でも聞き取れることも確かめる。

#### 対応攻撃のマルチロック（3D試作案）

マルチロック対応に設定した攻撃では、詠唱の有無を問わず、その攻撃ボタンを押している間に対象を選べる。画面内で射程と射線が通る敵のうち、騎士に最も近い一体に最初の印が付く。パッドでは最後に付けた印を起点に、右スティックを倒した画面上の8方向（上下左右と斜め）から選ぶ。たとえば右上に倒すと、印の右上に見える未選択の敵を画面上で近い順に一体追加する。スティックを中央に戻して再び倒すと次の一体を選べる。その方向に候補がいなければ今の印を保つ。上限は試作で三体。ボタンを離すと有効な対象に向けて攻撃を実行する。騎士のカメラロックと味方への集中攻撃先は個別に保つ。

敵・味方のAIも、対応攻撃の実行ごとに対象を複数持てる。普段の追跡や向きには従来の主標的一体を使う。主標的を最初の候補とし、攻撃者から見えて射程・射線が通る別の敵を追加する。攻撃が有効になる時点で対象の世代と射線を確認し、倒れたり遮蔽に入った相手の分は省く。飛翔体は残った相手に一発ずつ割り当て、接触攻撃は実際に当たった対象に一回ずつ命中する。攻撃が中断されたら、その実行に属するロックを解除する。地点指定の範囲攻撃は着弾時に被弾者を求める。

左右を味方に挟まれた騎士に敵の術師が三発を向ける場面で試す。術師の主標的がシスターでも、騎士に割り当てた一発だけは騎士の画面端に警告を出す。他の二発がそばを通るだけでは警告を増やさない。[既存AIの標的関係](../Assets/MyAsset/Core/AI/Core/AITargetRelations.cs)・[複数対象の検証記録](../docs/reports/experiments/2026-11-24_ai-terrain-gimmicks.md)

2Dの `CoreTestScene` では、騎士のスキルに試作用の追尾弾を設定している。パッドでは右肩ボタンを押したまま右スティックで標的を足し、右肩ボタンを離して発射する。キーボードではQの押下で最初の標的を選び、離して発射する。弱・強攻撃でも、使う `AttackInfo` の `multiLockRange` に射程を設定すると押している間に照準できる。[試作シーン](../Assets/Scenes/CoreTestScene.unity)

### 総力戦の指揮官とコンバットマネージャー（設計案）

| 担当 | 決めること | 橋での例 |
|---|---|---|
| 陣営ごとの指揮官 | 自陣営が知った脅威、プレイヤーの号令、各種の得意な役割、手の空いた味方を見て、任務に優先順位と必要数を付ける。味方が任務を引き受けたか、まだ間に合うかを見て再配分する。 | 「橋の正面に盾持ち一体」「別の一体はシスターの護衛」。プレイヤーが術師への集中を指示したら、手の空いた味方を向ける。敵の指揮官は敵側から見える戦況で動く。 |
| 遭遇ごとのコンバットマネージャー | 参加・離脱、戦闘の段階、増援を許す区間を把握し、同じ場所・対象に重なった要求を裁定する。占有範囲は入口や対象ごとに定め、無関係な場所での戦闘は並行して進む。 | 橋に一体分しか立てないとき、盾持ち二体の同時要求の片方だけを受理する。攻撃で怯んで到達できなくなった個体の予約が解けると、もう一体が引き継げる。 |
| 個体AIと行動実行 | 割り当てた任務に対し、その個体の作戦、足場、射線、硬直から実行手段を選び、受理・失敗・完了を返す。新しい号令を受けた時点と、技を切り替えられる時点を区別する。 | 跳躍中に護衛を頼まれた魔犬は、着地時に脅威が残っていれば向かう。その前に別の味方が術師を止めたら、追撃を続ける。 |

「狙われ数」は陣営を問わず現在その個体を標的にしている数。提案では、個体IDと陣営を使って「自分以外の味方が何体狙っているか」を読み分ける。これとは別に、任務を受けた個体と使う地点・期限を戦闘中だけ記録する。受理前の号令で人数を水増しせず、戦闘終了や個体交代で古い予約を解放する。騎士は引き続きプレイヤーが直接操作する。指揮官が任務の分担を見直すきっかけは、明示指示、脅威の出現、増援の到着、担当の失敗など、分担を変える理由が生じたときとする。召喚コストは編成の予算として管理する。[標的関係](../Assets/MyAsset/Core/AI/Core/AITargetRelations.cs)・[既存の号令定義](systems/AICore.md)

3Dで部隊配分を試す場面は、**橋幅一体、盾持ち二体、奥に敵の術師**という同じ部屋で、通常・護衛中の被弾・集中指示を比べる。味方二体が同時に空きを見ても正面には一体だけが入り、被弾で担当が空けば交代する。別の入口を守る部隊やプレイヤーの騎士まで足を止めないことを確かめる。

3Dの `GroupBattle3DTestScene` では、西側の橋を二体の盾持ちが正面と控えに分かれて守る。東側を通った騎士が奥の目標に入ると遭遇が完了する。カメラに映る相手や床への指示は、陣営の観測、対象の登録世代、同じ3D区画の接触面を照合する。F／十字キー下の短押しは発令、長押しして離すと号令枠を送る。[3D集団戦の試作部屋](../Assets/Scenes/GroupBattle3DTestScene.unity)

### 敵指揮官と騎士が共用する号令

詳細なAI設定画面で条件・優先順・モードを保存できるのはシスターだけ。召喚魔物には作者が種ごとの行動を与え、プレイヤーは編成と戦闘中の短い号令で共闘する。同種を複数呼んでも、頭数の分だけ設定画面を開く手間は生じない。

敵の指揮官がルールから「集合」を選んだときも、騎士が操作で「集合」を選んだときも、同じ号令IDを発行する。集合先は発令者自身で、受け手はその陣営のAI。敵味方が同じ橋で同時に集合をかけても、それぞれが自陣の発令者に戻る。号令ごとに使用者のビット属性を持たせ、両者とも使える「集合」と敵指揮官だけが使える「挑発」を区別する。敵側だけに許可した号令は騎士の枠に装備できず、入力から直接発行しても成立しない。

プレイヤーがカスタムするのは**騎士が持ち込む号令とその並び順**。部隊全体で一組を使う。たとえば同じ盾持ちを二体連れていても、「集合」の位置を変える操作は一回で済む。使用できる号令の例は「集合」「集中攻撃」「ここを守れ」「おまかせ」「ターゲット指示」の5種で、うち4種を持ち込む。すでに別の枠にある号令を選ぶと、二つの枠を入れ替える。「ターゲット指示」なら相手を決めていない味方に知らせ、「集中攻撃」なら交戦中の味方にも切り替えを求める。シスターの条件・優先順はそのまま利用する。

**操作方式は仮置き。** Unityの2D試作ではF／十字キー下の短押しで選択中の号令を出し、長押しして離すと次の枠へ送る。初期選択は「集合」。4枠の中身はプレイヤーの入力コンポーネントに保持する。ブラウザの比較用見本ではFで四方向のメニューを開き、矢印キーかクリックで確定し、Escで取り消す。どちらの操作でも、枠から取り出す値は同じ号令ID。Unityで騎士とAI付きのシスターを試せる場面はCoreTestScene。以下はブラウザでの配置例。[試作シーン](../Assets/Scenes/CoreTestScene.unity)・[入力設定](../Assets/InputSystem_Actions.inputactions)

| 方向 | 号令 | 誰がどう動くか |
|---|---|---|
| ↑ | 集中攻撃 | 開いたときに印を付けた敵を指揮官に伝える。届く魔物が攻撃を引き受ける。 |
| → | ここを守れ | 印が付いた床・入口を持ち場にする。盾持ちが橋を塞ぎ、射手は後ろから支援するなど、種ごとに手段が変わる。 |
| ↓ | 集合 | 召喚部隊とシスターが騎士のもとへ戻る。その場で追撃を切れない個体は安全に切り替えられる段階で向かい、合流したら通常の随行に戻る。 |
| ← | おまかせ | 今の手動指示を解く。魔物は種ごとの役割、シスターは保存した設定に戻る。集合地点への移動は要求しない。 |

3D総力戦では号令の宛先は陣営の指揮官。探索中も総力戦も同じ操作で、任務に必要な個体を割り当てる。騎士が橋の床を見て「ここを守れ」と指示すると、地面に旗が立ち、受けた味方に盾の印が出る。「防衛を受理 2体」で指示が届いたことが分かる。命令が終われば印が消え、編成やシスターの保存設定は維持する。

四方向メニュー案では、指揮を開いたときに選んだ敵や床を固定し、対象が消えた場合や橋の上か下かを特定できない場合には、該当する号令を無効表示にする。取消や発令失敗なら直前の有効な指示を保つ。受理した後に標的が消えた場合はその任務を終了し、担当は自律行動へ戻る。最初の操作試験は、術師への集中、橋の防衛、混戦からの集合とおまかせの違い、無効な対象と誤入力を確かめる。[ブラウザで試せる操作見本](ui/field-orders-mockup.html)

## 引き継ぐメカニクス

| 分野 | この企画での使い方 |

## 機能DBに登録する経路

機能名は `DungeonExpedition_AllyRoster`。遠征、召喚編成、3Dの集団戦とボス戦、マルチロック、攻撃予告の実行経路を追跡する。登録内容は `python tools/feature-db.py call-paths DungeonExpedition_AllyRoster` で確認できる。[登録マニフェスト](call-paths.json)・[ローカルDBの復元と3経路のハンズオン](../docs/reports/handoffs/2026-11-24_multilock-and-attack-warnings.md)

| 優先 | 経路 | 実装時に通す対照ケース | DBキー |
|---|---|---|---|
| 最初の探索 | NPCイベントから召喚解放 | マップの同種を倒しても未解放。指定の依頼・物語戦闘の結果で一度だけ解放し、報酬通知の再送でも重複しない。 | `unlock-npc-aid` |
| 最初の探索 | コストと体数による編成 | 同種2体を別々に数える。コスト上限ちょうどを許可し、1体分超過する変更を拒否したときは元の編成を保つ。 | `compose-costed-squad` |
| 最初の探索 | シスターの召喚と各個体の出撃 | 同種の味方に別々の個体IDと標的を与える。配置先が塞がって呼べない場合に、実体や使用枠だけが残らない。 | `deploy-sister-summons` |
| 最初の探索 | 解放・編成・周回の保存と復元 | 再起動して同種の体数まで復元する。新項目のない旧セーブも開ける。探索再開時に、以前の部屋の臨時枠を持ち込まない。 | `restore-expedition-progress` |
| 集団戦 | 指定遭遇で増援枠を開閉 | 人数とコストを設定した集団戦で増援できる。集団戦フラグはボス戦と組み合わせられ、勝利・撤退・再挑戦の境界で枠が重ならない。 | `expand-designated-encounter` |
| 指揮の試作 | 操作と敵AIから共通の号令を発行 | 同じ集合で両軍がそれぞれの発令者へ向かう。敵専用の挑発は騎士の装備候補・発令の両方で拒否する。 | `dispatch-faction-field-order` |
| プレイヤー操作 | 対応攻撃を押している間、画面の8方向でマルチロック | 最初は騎士に近い敵を選ぶ。最後の印から右上にいる敵を一体追加し、候補がない方向を入力しても印は変わらない。 | `select-player-eight-way-multilock` |
| 飛翔体の試作 | 敵・味方AIが一回の攻撃で各弾に対象を割り当てる | 主標的を維持したまま三体を選び、発射前に一体が失効したら残る二体へ一発ずつ出す。中断された攻撃のロックは残らない。 | `assign-ai-cast-projectile-targets` |
| 集団戦の予告 | 騎士へのロックと範囲攻撃を別々に伝える | 騎士宛ての弾だけ画面端に方向を示す。シスター宛ての爆発弾は床の範囲だけ、通常の流れ矢は表示なし。危険な近接は警告音で判別する。 | `show-lock-and-area-warnings` |
| 魔物溜まり | 3Dの集団戦と目標達成 | 騎士の簡易指揮を受けて担当が分かれ、無効な指示が別の敵や階へ流れない。任務後は種ごとの行動へ戻り、騎士自身が目標に到達できる。 | `coordinate-3d-group-battle` |
| ボス戦 | 3Dボス戦の開始、フェーズ遷移、撃破 | 配置ボスがフェーズを移行し、対象個体の撃破でクリアする。集団戦を兼ねる場合は臨時増援を解除する。 | `complete-native-3d-boss-encounter` |
| 二周目 | クリア後に次の周回を開始 | プレイヤーが確認してから同じスロットに次周を保存し、開始シーンへ移る。保存に失敗した場合は同じ周回で再試行できる。 | `begin-next-expedition-playthrough` |
| 二周目 | 対象ボスの召喚解放 | 初周の撃破、二周目の対象外ボス、条件を満たした対象ボスを区別し、解放したボスを実際の編成・召喚へ渡す。 | `unlock-ng-plus-boss-aid` |

別のローカルDBへ取り込む場合、この親機能の初回登録は `python tools/feature-db.py add DungeonExpedition_AllyRoster --category system`。その後、取り込む経路を含むJSONを `import-call-paths --file` に渡す。全体マニフェストを使う場合は、そこに登場する他の親機能も先に登録しておく。

`ExpeditionQuest3DTestScene` では、工兵長のそばでE／パッドのY・△を長押しして依頼を受ける。北の測量標へ行って報告すると、Quest Machineの成功通知で工兵が解放される。シスターとの会話から「探索編成を開く」を選び、デッキを保存または読み込み、人数・コストを確認して編成を確定する。シスターに改めて話しかけて「確定した編成を呼ぶ」を選ぶと出撃する。会話、依頼進捗、解放、編成とデッキは同じゲームのセーブスロットで扱う。[遠征の3D試作部屋](../Assets/Scenes/ExpeditionQuest3DTestScene.unity)

## システムと制作範囲

戦闘・成長には既存のSoAデータ、GameManager、入力・装備・魔法・インベントリ・UIを使う。AIの観測と行動実行、装置、既存召喚の寿命管理、アリーナ・ボスのフェーズ管理が接続候補になる。この作業コピーにある2D物理、タイルマップ、固定召喚枠は従来プロトタイプの実装。3D区画の通行・射線・出現位置・カメラと可変編成は段階1・2で実地確認する。[既存システム設計](dependency-graph.md)・[召喚システム](systems/SummonSystem.md)

タイトル、ゲーム本編、加算ロードするUI、ボス、チャレンジのシーン構成を引き継ぐ。3Dの画面では、骸骨騎士、シスター、敵味方、大技の範囲を混戦中も識別できることを優先する。音声・カメラ方式の詳細は制作時に決める。既存の範囲は手作りダンジョン、騎士一人の直接操作、拾得型の能力成長で、オンラインマルチ・ランダム生成・クラフト・スキルツリーは対象外。

**調整として残すもの**は、通常と総力戦の人数・コストの実数、魔物ごとの値、呼び直しの条件、対象ボスと解放イベント、二周目への引き継ぎ範囲。まずは同じ部屋・異なる編成で、騎士が何をできるようになったかを比べる。
